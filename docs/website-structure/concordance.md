# Concordance

The DOJ uses Concordance for e-discovery, as confirmed by the following points:

## DataSet ZIP files

The DOJ used to serve zip files as a bulk download option.
Each zip file had the following nested folder structure:

```bash
DataSet n/                  # Root folder for dataset n
└── VOL0000n/               # Volume folder corresponding to dataset n
    ├── DATA/               # Contains index and data reference files
    │   ├── VOL0000n.OPT    # CSV-like file: lists all file names & relative paths; Concordance Opticon load file
    │   └── VOL0000n.DAT    # Custom-format version of concordance load file
    │
    ├── IMAGES/             # Contains PDF files of dataset
    │   ├── 001/            # Subfolder grouping PDFs (numbered)
    │   │   └── ...         # Actual PDF files or "No Images Produced" placeholders
    │   ├── 002/            # Next numbered folder
    │   │   └── ...
    │   └── ...             # More numbered folders as needed
    │
    └── NATIVES/            # Contains other associated files in their original formats
        ├── 001/            # Subfolder grouping native files
        │   └── ...         # Files in various formats
        ├── 002/            # Next numbered folder
        │   └── ...
        └── ...             # More numbered folders as needed
```
Terms that will be used from now on:
- **Images**: Regular PDF files
- **Native placeholders**: "No Images Produced" PDF files
- **Natives**: Non-PDF files


This folder structure matches up exactly with Concordance production exports. [Concordance® Native Viewer, Administrator's Guide, page 96](https://lexisnexis.com/documents/cndownload/Concordance%20Native%20Viewer%20Administration%20Guide.pdf#page=96) contains a screenshot of the folder structure, which matches what is observed in the ZIP files:

## Individual files

Each dataset seems to have its own directory on the DOJ's Akamai file server: `Dataset%20n/`
In that directory, all the images, natives and native placeholders are accessible via file name (excluding deleted ones). There seem to be no other individual files present.

### Images

Each image file contains:
- the picture of whatever it was pre-conversion with redactions applied
- OCRed text post redactions
- Bates number (`EFTA...`)
All of them have exactly 2 revisions, indicated by the existence of 2 `%%EOF` markers. The second revision always contains only the Bates number as raw unOCRed text.

### Native Placeholders

Native placeholders are PDF files similar to images, but instead of the picture they contain the text `No Images Produced` and sometimes additionally contain the text `Native Placeholder` as raw unOCRed text. It is not known why only some of them contain the text `Native Placeholder`.

Locating native placeholders and manually replacing the extension is currently the main method used for locating natives, considering the absence of bulk download options.

The native placeholder PDFs are generated by [ReportLab](https://www.reportlab.com/), as indicated by the included messages like `ReportLab generated PDF document` at byte offset `0xF`. The timestamps at byte offset `0x208` are always different, which indicates that each native placeholder was fully regenerated instead of using a template placeholder and adding the bates number later.

Some rare instances of placeholders aren't generated by ReportLab, but by Microsoft Word. There is no clear reason for this. It is also not known if the generation of native placeholders is standard Concordance behaviour, plugin behaviour, a custom feature implemented by the request of the DOJ, or manual behaviour implemented by DOJ staff.

### Natives

Natives are non-PDF files that are either accessed through the `NATIVES` folder of a ZIP file or through native placeholders. Since DataSet 9, 10 and 11 never had zip files released, the only way to locate these files is through native placeholders followed by brute forcing of the file extension or through the direct search of natives in dataset index pages.

Using that, it was possible for us to figure out most file extensions of natives. DataSet 9 contains some unknown ones; DataSet 10 contains one unknown one.

Natives are never pictures, as those would have been converted to images.

## DOJ and Concordance

The files themselves contain instances of the DOJ previously using Concordance for Epstein files related e-discovery. This [Contract](https://www.justice.gov/epstein/files/DataSet%209/EFTA00071881.pdf) details a government task order for specialized document digitization services and creation of several e-discovery load files, including a Concordance `.dat` file. The contract itself does'nt contract CloudNine (current owner of Concordance); however the request of a Concordance .dat file strongly implies the usage of Concordance: `"Concordance .dat file with fields: BEGDOC, ENDDOC, FOLDER INFORMATION, BOX INFORMATION, TEXTPATH", EFTA00071884`.

Some instances of publicly accessible servers owned by the DOJ that run Concordance exist, however they will not be listed here for security reasons.
